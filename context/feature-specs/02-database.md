# DATABASE PREPARATION SPECIFICATION

Read **GEMINI.md**, **architecture-context.md**, and **database-model.md** before implementing the database layer.

## OVERVIEW
This document defines the technical execution plan for setting up the persistence layer. We use **SQLite** for storage and **Drizzle ORM** for type-safe database interactions.

**Database File**: `local.db` (root directory).
**Gitignore Requirements**: Ensure `local.db` and all SQLite-related files (`*.db`, `*.db-journal`, `*.db-shm`, `*.db-wal`) are added to `.gitignore`.
**Schema Directory**: `src/db/schema` (domain-driven schema files).
**Client Directory**: `src/db/index.ts` (database connection and export).

---

## 1. SCHEMA DEFINITIONS
Schemas must be defined using Drizzle's SQLite-specific types. All timestamps should be stored as integers (Unix timestamps).

### User Schema (`src/db/schema/users.ts`)
- `id`: `text` (UUID), Primary Key.
- `email`: `text`, Unique, Not Null.
- `passwordHash`: `text`, Not Null.
- `name`: `text`, Not Null.
- `roleId`: `text`, References `roles.id`.
- `createdAt`: `integer`, Default `Date.now()`.

### Event Schema (`src/db/schema/events.ts`)
- `id`: `text` (UUID), Primary Key.
- `title`: `text`, Not Null.
- `description`: `text`, Not Null.
- `date`: `integer`, Not Null (Event occurrence).
- `location`: `text`, Not Null (General location).
- `addressId`: `text`, References `addresses.id`.
- `organizerId`: `text`, References `users.id`.
- `isPromoted`: `integer` (Boolean 0/1), Default `0`.
- `imageUrl`: `text`, Optional.
- `createdAt`: `integer`, Default `Date.now()`.
- `updatedAt`: `integer`, Default `Date.now()`.

### Address Schema (`src/db/schema/addresses.ts`)
- `id`: `text` (UUID), Primary Key.
- `city`: `text`, Not Null.
- `street`: `text`, Not Null.
- `postalCode`: `text`, Not Null.
- `createdAt`: `integer`, Default `Date.now()`.

### Role Schema (`src/db/schema/roles.ts`)
- `id`: `text` (UUID), Primary Key.
- `name`: `text`, Not Null (e.g., 'admin', 'organizer').
- `isAdmin`: `integer` (Boolean 0/1), Default `0`.
- `createdAt`: `integer`, Default `Date.now()`.

## 2. DATABASE CLIENT SETUP
The database client should be initialized in `src/db/index.ts`.

- Use `better-sqlite3` as the driver for the local SQLite file.
- Export a `db` instance for use in Server Functions.
- Enable logging in development mode.

```typescript
import { drizzle } from 'drizzle-orm/better-sqlite3';
import Database from 'better-sqlite3';
import * as usersSchema from './schema/users';
import * as eventsSchema from './schema/events';
import * as addressesSchema from './schema/addresses';
import * as rolesSchema from './schema/roles';

const sqlite = new Database('local.db');
export const db = drizzle(sqlite, { 
  schema: { ...usersSchema, ...eventsSchema, ...addressesSchema, ...rolesSchema } 
});
```

## 3. MIGRATIONS & TOOLING
Use **Drizzle Kit** for managing the database lifecycle.

- **Config**: `drizzle.config.ts` in the root directory.
- **Commands**:
    - `npm run db:generate`: Generate SQL migration files.
    - `npm run db:push`: Push changes directly to the database (for rapid development).
    - `npm run db:studio`: Launch Drizzle Studio for visual data management.

---

## 4. SEEDING STRATEGY
A seeding script `src/db/seed.ts` should be implemented to populate the database with initial data for development.

- Create at least one default "System Organizer" user.
- Insert example events from `database-model.md`.
- Use `ts-node` or `tsx` to run the seed script.

---

## 5. VALIDATION & TYPES
- Use **Zod** schemas (in `src/lib/validations`) that match the database schema for form handling and API validation.
- Export TypeScript types from the Drizzle schemas using `InferSelectModel` and `InferInsertModel`.

---

## 6. GIT & SECURITY
- **Sensitive Data**: Never commit the `local.db` file or any other `.db` files.
- **Environment Variables**: If database credentials or paths are moved to `.env`, ensure they are properly loaded and never committed.
- **Migrations**: While the database file is ignored, the migration files generated by Drizzle Kit in the `drizzle/` directory **should be committed** to ensure schema consistency across environments.
